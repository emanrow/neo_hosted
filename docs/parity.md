# Parity with the desktop

What a writer gets in a browser compared with desktop NEO. ✔ same code, same files. ◐ works, with a browser-shaped difference. + hosted only. ✘ not yet. — does not apply.

| Desktop | Hosted | Notes |
|---|---|---|
| Shelves, books, chapters, notes, outline, darlings, stickies, goals | ✔ | the same `app.js`, the same files |
| Covers: seeded art, uploaded images | ✔ | upload is a raw `POST /api/cover:upload`; the shelf fetches `/library/<book>/<file>` |
| Painted covers (OpenAI) | ✔ | `art.js` runs on the server with the writer's own key, encrypted at rest |
| Spellcheck pass, suggestions, learned words | ✔ | one Hunspell per language shared by all writers; a writer's `customWords` are laid on top at check time, never added to the shared instance |
| Export txt, md, html, docx, epub | ✔ | built by `app.js` as before; the browser downloads the file. The EPUB leaves with the writer's body face as font files in the book and a drop cap on the chapters (`web/public/web-epub.js`, laid over the editor's entries at download time; readers may override both), and every pull request runs epubcheck on an export ([testing.md](testing.md#the-epub-under-epubcheck)) |
| Export PDF, ⌘E email snapshot | ◐ | with the printer deployed (`print/`, [deployment.md](deployment.md#railway) step 9): a small dialog takes the trim size (5.5 × 8.5 in, 6 × 9 in, A5, Letter, A4) and the scene-break style (asterisks, an ornament, a blank line), remembers them, and a book-shaped PDF downloads, laid out by Chromium and Paged.js with mirrored margins, running heads (author verso, title recto), page numbers in the outer corners, chapters opening on a recto, a numbered contents page and bookmarks, the chosen body font inside it (`web/public/web-print.js`, `print/book.css`); the desktop prints Letter or A4 with 1 in margins and no running numbers on front matter, so the hosted PDF is the more finished of the two. ⌘E downloads the snapshot and opens the mail draft to drag it into. Without the printer the browser opens the export as a print view ("Save as PDF") |
| Import .docx / .txt / .md | ✔ | the browser uploads each file as raw bytes to `POST /api/import:upload`; the parser is `import-parse.js` at the repository root, the same module `main.js` uses, so chapter detection cannot drift between editions |
| Daily zip backups | ✔ | per writer, on the volume; with Postgres the zip is written from the rows. Off-site copies are on the backlog |
| Delete a book | ✔ | with Postgres the rows are marked trashed and kept; without, the folder moves to `Trash/` inside the library, named with a timestamp. The bridge says where it went |
| Download Library… (File menu) | + | hosted only: the whole library as the desktop folder, zipped by the server (`GET /library.zip`); it opens in desktop NEO |
| Menus and shortcuts | ✔ | a hover-revealed bar at the top edge, Alt or F10 for the keyboard; same labels, same messages. On a touch screen a ☰ button opens it, a tap opens a flyout, and at phone width a menu drops as a sheet |
| Share… (File menu) | + | hosted only: a book, or the chapter the caret is in, published as a read-only page at `/s/<token>` for anyone with the link (`web/public/web-share.js`, `web/lib/share-store.js`). The page is a snapshot made by the editor's own Web Page exporter; publishing again updates it under the same link, Unpublish takes it down; where the browser has a share sheet (phones), Share… opens it with the link. Not indexed by search engines; the link is the writer's to hand out |
| On a phone | ◐ | the hosted edition is the only NEO in a phone's browser: `web/public/web-mobile.js` and the touch and narrow-width rules in `web.css` give the menu a button, the chapter and notes panes an edge swipe (as in NEO Pocket), the bottom bar a fixed place, and the page the whole width. No on-screen keyboard handling or share sheet yet; Pocket remains the phone app |
| Interface language, 10 languages | ✔ | saved per writer; the sign-in page and its errors follow the browser's language (`web/locales/`), since no one is signed in yet to have a saved one |
| Full screen | ✔ | the browser's Fullscreen API |
| History (File → History…) | + | hosted only: every save of a chapter is kept in the revision log; the panel previews any one, shows what changed between it and the draft now as a blackline (Show Changes), and restores it, the replaced words going to Darlings. [architecture.md](architecture.md#a-writers-corner-of-the-volume) |
| Branches (File → Branches) | + | hosted only: whole alternate drafts of a book, made from the draft you are in, switched with a reload; each keeps its own history. Compare & Merge… brings one into the draft you are in, paragraph by paragraph, with a blackline and a choice on each place changed in both. Side by Side… reads this draft and another in two columns, one chapter at a time, scrolled together. [architecture.md](architecture.md#a-writers-corner-of-the-volume) |
| Send Feedback… (Help menu) | + | hosted only, when email and `NEO_ADMIN_EMAILS` are set: a note typed in the writing room goes to the owner's inbox (`web/public/web-feedback.js`, `feedback:send`). An address in `NEO_GUESTS_OF_HONOR` gets the same panel once, unasked, as a welcome and thank-you |
| Timeline… (View menu) | + | hosted only, the first room off the hallway: the book's events in story order with a story-time, a title, a place, the characters there and a chapter link, reordered by drag, and a chart above the list with one swimlane per place and a coloured line per character across them; sheets of time (alternate timelines) as tabs over the chart, with a marker where a character crosses between sheets; an event may run through to a later chapter (`web/public/web-timeline.js`). Stored as `timeline.json` beside `darlings.json` through the desktop's own sidecar channels; desktop NEO ignores the file |
| Mind Map… (View menu) | + | hosted only, the second room off the hallway: nodes on a canvas, dragged, linked, tied to chapters, zoomed with − 100% + or ctrl/⌘ + wheel (`web/public/web-mindmap.js`). Stored as `mindmap.json` beside `darlings.json` through the desktop's own sidecar channels; desktop NEO ignores the file |
| Map… (View menu) | + | hosted only, the third room off the hallway: an uploaded image or a blank sheet with pins that carry a label, a note and a chapter (`web/public/web-map.js`). Pins in `maps.json` through the desktop's own sidecar channels; the image as `map-<ts>.<ext>` beside the cover, served from `/library/<book>/<file>`; desktop NEO ignores both |
| Handwriting… (View menu) | + | hosted only, the fourth room off the hallway: pages of strokes drawn with a stylus, a finger or a mouse, kept as points with the pen's pressure in `handwriting.json` through the desktop's own sidecar channels and drawn as SVG ribbons (`web/public/web-handwriting.js`); Export SVG… downloads a page; never OCR'd; desktop NEO ignores the file |
| Auto-update, Check for Update | — | the site is always current; the item is gone from the menu |
| Library Folder… | — | the server keeps the library (rows in Postgres, or a folder on the volume); Download Library… is the way out |
| Body Font: Libron, Literata, EB Garamond, Crimson Pro | + | hosted only, the first of the typography work: four book faces for print and e-readers (SIL OFL, licences in `fonts/`), each in regular, italic, bold and bold italic, declared in `web/public/web.css` and listed by `web/public/web-menu.js`; the editor resolves the family name through its own `bodyFontStack`, and an EPUB or print export embeds the chosen face as it does the desktop's bundled ones |
| Other Font… (local font picker) | — | left out of the menu; `queryLocalFonts` is Chrome-only and needs a permission prompt |

## Where the differences live

Every difference above is in `web/public/web-bridge.js` or `web/public/web-menu.js`, never in `app.js`. That is the rule from AGENTS.md ("Pocket-only behavior belongs in `pocket-bridge.js`") applied to a third doorway. If a parity gap cannot be closed from the bridge, say so in the backlog rather than branching the editor.

## Accelerators

The native menu used to catch these; `web-menu.js` does now: ⌘E, ⌘, (Goals), ⌘F, ⌘0, ⌘⇧I, ⌘⇧L/C/R/J (align), ⌘⇧T, ⌘⇧O, ⌘⇧F. `app.js` already handles ⌘; ⌘+ ⌘− and ⌘/ inside the editor by character, so those stay out of the table (one press, one action). Browsers keep a few for themselves (⌘⇧I opens devtools in Chrome); the menu item still works by click.
