## Rooms off the hallway

Each of these is a sidecar beside the book's files and a tab or pane that stays shut until opened. None of them writes into chapter HTML.

11. **AI throughout**, only ever at the writer's request and never while typing: ask a question of the manuscript, name a placeholder, continue a scene into Darlings (never onto the page), paint covers as today. Keys per writer, encrypted as today. Upstream NEO is firm that it has no generative tools; this fork adds them as opt-in rooms off the hallway, not squiggles on the page.

## Done

- **Images in the bucket** (2026-10-06): `web/lib/image-store.js` sits between the upload routes, the painting and `serveCover` and the library. With `NEO_BACKUP_BUCKET` set, covers, paintings, map sheets and a chapter's pictures go to the bucket under `images/<writer>/<book>/<file>` and the library keeps a one-line stub in each one's place, so the folder layout and every name rule stay the library's; without a bucket nothing changes. Reads follow a stub into the bucket and still serve images stored before it existed; the download and the removed-account zip put the bytes back (`exportZip(fileBytes)` on both libraries); a bucket that refuses leaves the bytes with the words. `object-store.js` learned GET.
- **One disk module** (2026-10-06): `web/lib/files.js` and the catalog, recovery and backup-walk code it shared with `main.js` by copy are now `library-disk.js` at the repository root, required by both editions the way `import-parse.js` is; the port-in-step rule is down to `dailyBackup` and the trash ([architecture.md](architecture.md#what-is-shared-with-mainjs-and-what-is-still-a-port)). `scripts/library-disk.test.js` checks the module on its own and CI runs it with the parser's test.
- **Footnotes** (2026-10-06), the last step of the typography order: Format → Insert Footnote… (`web/public/web-footnotes.js`) plants a numbered call at the caret and opens a pad for the note; the notes are `footnotes.json` beside the chapters (`json:read`/`json:write`, nothing server-side), numbered by order in the chapter, and a call deleted with the words around it drops its note from every export. The PDF sets each note at the foot of its page with Paged.js's `float: footnote`; the web page lists a chapter's notes under it; the EPUB gets `epub:type="noteref"` calls and `epub:type="footnote"` asides (epubcheck still clean); the Word file real footnotes in `word/footnotes.xml`; plain text and Markdown a numbered list under the chapter. The call's text is a private-use mark that rides `app.js`'s builders the way a picture's does; the editor never learns about it. Left for later: endnotes as a choice, and notes on the front pages.
- **Pictures in a chapter** (2026-10-06), the illustration step of the typography work: Format → Insert Picture… (`web/public/web-figures.js`) uploads an image to `fig-<ts>.<ext>` beside the cover (`POST /api/figure:upload`, `addFigure` in both libraries, never deleted) and plants a paragraph at the caret that the page draws the picture above; its words are the caption, Enter under it goes on with the chapter. The web page, the PDF and the EPUB carry a `<figure>` with the caption in place (the bytes inlined for the page and the printer, `OEBPS/images/` in the EPUB); the Word file an inline drawing with the caption centred under it (`word/media/`, a relationship and a content type each); the epubcheck run exports a book with two pictures and builds the Word file too. Each picture's paragraph carries a private-use text mark through `app.js`'s builders, which is how the EPUB and Word hooks find it again.
- **EPUB polish** (2026-10-06): the EPUB export carries the writer's body face as font files (the four hosted book faces and the desktop's bundled ones; readers may still override) and opens each chapter with a drop cap unless the editor hides it, laid over `app.js`'s own entries at download time by `web/public/web-epub.js`. Every pull request now exports a book through the real exporter and runs epubcheck on it with warnings as failures ([testing.md](testing.md#the-epub-under-epubcheck)). The EPUB 3 navigation was already there.
- **Book faces** (2026-10-06), the first step of the typography work: Libron, Literata, EB Garamond and Crimson Pro under Format → Body Font, each in four styles, OFL licences in `fonts/`, declared in `web/public/web.css` and listed by `web/public/web-menu.js`; an EPUB or print export embeds the chosen one.
- **The printer** (2026-10-06), the second step: `print/`, headless Chromium with Paged.js as its own Railway service, behind `POST /api/export:pdf`; Export → PDF and the ⌘E snapshot download a book laid out at 5.5 × 8.5 in with mirrored margins, 11-on-15 justified type, widow and orphan control, page numbers, a numbered contents page and bookmarks, the chosen face embedded; the browser's print view remains the fallback. `print/book.js` already knows 6 × 9, A5, Letter and A4.
- **Print conventions** (2026-10-06), the third step: Export → PDF asks for the trim size (5.5 × 8.5, 6 × 9, A5, Letter, A4) and the scene-break style (asterisks, ornament, blank line) in a small dialog (`web/public/web-print.js`) and remembers the answer per writer (`print:settings`, in `settings.json`); the printer sets running heads (author verso, title recto), folios in the outer corner, none on front matter or an opener, and opens every chapter on a recto (`print/book.css`). Illustrations and footnotes followed the same day.
- **Hyphenation and the page-count spike** (2026-10-06): headless Chromium never gets a hyphenation dictionary, so the printer puts soft hyphens in itself (`print/hyphenate.js`, Liang's patterns per language). The pretext.js spike found its line breaks match Chromium's on 99.9% of paragraphs for three of the four faces and a page model lands within ±2% of the printer's count in a quarter of a second, so the live "about N pages" beside the word count was built the same day (`web/public/web-pagecount.js`, pretext served from `web/vendor/`, the saved trim from `print:settings`, a click cycles the trims).
- **Handwriting** (2026-10-05), the fourth room off the hallway: View → Handwriting… (`web/public/web-handwriting.js`) is a pad of pages for a stylus, a finger or a mouse: four inks, three widths, an eraser, undo, a title and a chapter per page. Strokes are kept as their points in `handwriting.json` beside `stickies.json` (the desktop's own sidecar channels) and drawn as SVG paths; nothing is ever read as text. A pen's pressure sets each point's width (a mouse draws evenly), and Export SVG… downloads a page as a file.
- **Map map** (2026-10-05), the third room off the hallway: View → Map… (`web/public/web-map.js`) is a sheet, an uploaded image or a blank grid, with pins dropped where things are; each pin has a label, a note and a chapter, and jumps to it. Pins are `maps.json` beside `darlings.json` as fractions of the sheet (the desktop's own sidecar channels); the image is `map-<ts>.<ext>` beside the cover, uploaded raw at `POST /api/map:upload` and served with the covers (`setMapImage` in both libraries). Still to come: drawing on the sheet, and more than one map per book.
- **Mind map** (2026-10-05), the second room off the hallway: View → Mind Map… (`web/public/web-mindmap.js`) is a canvas of nodes dragged into place, linked to one another with lines, and tied to chapters; a tied node jumps to its chapter. `mindmap.json` beside `darlings.json`, through the desktop's own sidecar channels like the timeline. Zoom came on 2026-10-05: − 100% + in the toolbar, or ctrl/⌘ + wheel (a trackpad pinch) about the pointer. Still to come: placeholders as nodes.
- **Timeline** (2026-10-05), the first room off the hallway: View → Timeline… (`web/public/web-timeline.js`) lists the book's events in story order, each with a time in the story, a title, a place, the characters there and the chapter it is told in; drag or nudge to reorder, a chapter's name jumps to it. Above the list a chart draws the events as swimlanes, one per place (a town, a room, a year, a world: whatever the story needs), story order left to right, chapter boundaries dotted, and one coloured line per character joining the events they are in, so a character's movement through time and space reads as a single stroke. Click a mark to find its row, double-click to open its chapter. Sheets of time came the same day: an alternate timeline beside the main one (a split world, a second frame of reference); each event belongs to a sheet, the chart shows one sheet at a time with tabs above it, and a character whose previous or next event is on another sheet gets a marker at the jump naming that sheet. The file is `timeline.json` beside `darlings.json` (`lanes`, `characters`, `sheets`, `events`), read and written through the desktop's own `json:read` / `json:write` channels, so branches, backups and the zip carry it and the server learned nothing new; the order is the array order and the time is text the writer reads, never parsed, so a story can run backwards or twice. An event told across chapters (a siege over four of them) has a "through" chapter under its row; the chart runs a bar on from its mark and names the chapter it ends in. Print Chart… (2026-10-06) makes a landscape sheet of it: every sheet of time, cut into page-wide segments with the lane names repeated and a character's stroke running on to the edge, the events listed under each; it goes to the printer as a sheet of its own size (`layout=sheet`, no book styles) or, without one, to the browser's print view.
- **The owner's page** (2026-10-05): `/admin` (`web/lib/admin-page.js`) for the oldest account or `NEO_ADMIN_EMAILS`: every account with its books, library size, zips and public pages, the server's settings, the volume's size, and Remove with the address typed back; the library is zipped under `removed/` first.
- **Public sharing** (2026-10-05): File → Share… (`web/public/web-share.js`) publishes the book, or the chapter the caret is in, as a read-only page at `/s/<token>` (`web/lib/share-store.js`, migration `004-shares`, files under `shares/` on a laptop). The page is the editor's own Web Page export, taken as a snapshot; publish again to update, Unpublish to take down. On a phone the row has Share…, the browser's own share sheet (2026-10-05). Still to come: an excerpt smaller than a chapter.
- **The sign-in page in every language** (2026-10-05): `web/locales/<code>.json` carries the hosted edition's own strings per upstream language, laid over upstream's `locales/` by `web/lib/i18n.js`; `web/lib/login-page.js` renders `login.html` in the browser's language and the auth errors speak it too. The confirmation and reset emails followed on 2026-10-05: `mail.js` takes the same translator, keyed to the browser that asked.
- **Off-site backups** (2026-10-05): `web/lib/object-store.js`, a Signature Version 4 `PUT` over `node:crypto` and `fetch`; with `NEO_BACKUP_BUCKET` and the AWS SDK's four variables set, the hourly sweep copies each writer's daily zip into the bucket as `<writer id>/neo-backup-<date>.zip`, marks it `.offsite` on the volume, and retries a failed copy every sweep. Railway's own Postgres backups are a dashboard switch, not code.
- **Mobile pass** (2026-10-05): a viewport meta slotted in by `web/lib/page.js`, `web/public/web-mobile.js` (a ☰ button for the menu bar, edge swipes for the panes, on `(hover: none)` screens only) and touch and narrow-width rules in `web.css`; flyouts open on tap. Sign Out and the rest of the menu are reachable on a phone.
- **Words in Postgres** (2026-10-05): `web/lib/pg-library.js` and migration `003-library`; with `DATABASE_URL` every library call lands on rows laid out as the desktop folder, one per file, keyed by book and branch, and the first boot imports each writer's folder from the volume. `GET /library.zip` (File → Download Library…) and the daily zip write the folder back out. Storage stage D; the folder library stays for laptops and tests.
- **Revision log** (2026-10-05): `web/lib/revisions.js`, the `revisions` table; every `chapter:write` that changed the words appends a snapshot or paragraph-grain diff, hash-chained with its timestamp. `revision:list`, `revision:read`, `revision:verify` answer. Storage stage B.
- **Branches** (2026-10-05): File → Branches in the hosted menu; `web/lib/branches.js` keeps each as a copy of the book folder under `.branches/`, the library follows the active one, the revision log keys by it. Compare & Merge… (`web/lib/merge.js`, `web/lib/branch-merge.js`) brings a branch into the draft you are in with a three-way merge at paragraph grain, a blackline per chapter and a choice on each conflict. Side by Side… (`branch:read`) shows this draft and another in two columns, chapter by chapter, scrolled together, read only. Storage stage C.
- **Feedback, and a welcome for a guest of honor** (2026-10-05): Help → Send Feedback… (`web/public/web-feedback.js`, `feedback:send`) emails the owner (`NEO_ADMIN_EMAILS`) what a writer typed, through `web/lib/mail.js` and its rations. An address in `NEO_GUESTS_OF_HONOR` is welcomed once, on first opening the room, with a thank-you for the editor and the books and the same form; `welcome:seen` keeps it to once.
- **History panel** (2026-10-05): File → History… in the hosted menu (`web/public/web-history.js`) lists the chapter's saves, previews one, restores one.
- **Accounts in Postgres** (2026-10-05): `web/lib/db.js` and `PgUserStore`, chosen by `DATABASE_URL`; `users.json` is imported once on the first boot and kept beside the volume as `users.json.imported-<date>`. Storage stage A.
- **Email** (2026-10-05): Resend behind `web/lib/mail.js`; new writers confirm their address, a forgotten password comes back by a link that works once. `RESEND_API_KEY`, `NEO_MAIL_FROM`, `NEO_PUBLIC_URL` turn it on.
- **Checks on every PR** (2026-10-05): `.github/workflows/hosted.yml` runs the hosted suite, the lint, the parser tests and boots the Docker image.
- **Import** .docx / .txt / .md (2026-10-03): the parser left `main.js` for a shared `import-parse.js`; the server exposes `POST /api/import:upload`; the bridge wires `importPick` and `importFiles`. One parser for both editions.
